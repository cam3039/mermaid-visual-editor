## 2024-05-24 - Modal Accessibility and Focus Management
**Learning:** Import modal was missing screen reader context (`role="dialog"`, `aria-labelledby`, `aria-describedby`) and live regions for asynchronous parsing feedback. Keyboard focus states on buttons were also missing.
**Action:** When building modals, always include proper ARIA roles and labels, ensure focus visible states on all interactive elements, and use `aria-live` regions for any dynamic status updates (like the parser feedback) so screen readers can announce them.

## 2024-05-25 - Neumorphic Keyboard Accessibility
**Learning:** Custom "neumorphic" buttons (`NeuBtn`, `NeuIconBtn`, `ZoomBtn`) applying CSS via inline style objects inherently overwrite or bypass default browser/Tailwind ring utilities, resulting in no focus indication for keyboard-only users.
**Action:** Always add explicit generic utility classes like `className="focus-visible:outline focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-indigo-500"` when building accessible custom interactive UI wrapper components. Using `focus-visible` ensures mouse users don't see the outline on click while still assisting keyboard-navigation users.
