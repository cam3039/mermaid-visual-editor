## 2024-05-24 - Modal Accessibility and Focus Management
**Learning:** Import modal was missing screen reader context (`role="dialog"`, `aria-labelledby`, `aria-describedby`) and live regions for asynchronous parsing feedback. Keyboard focus states on buttons were also missing.
**Action:** When building modals, always include proper ARIA roles and labels, ensure focus visible states on all interactive elements, and use `aria-live` regions for any dynamic status updates (like the parser feedback) so screen readers can announce them.
## 2024-05-24 - Accordion Accessibility\n**Learning:** When building collapsible/accordion UI components, it is critical to always render the content container and toggle its visibility via CSS (e.g., `display: open ? 'block' : 'none'`) rather than conditional rendering. This ensures that the `aria-controls` ID referenced by the toggle button remains valid in the DOM even when the accordion is closed.\n**Action:** Always map `aria-expanded` and `aria-controls` on accordion buttons, generate unique IDs using `useId()`, use `focus-visible` classes for keyboard navigation, and strictly use CSS display toggling for the content wrapper.
